The to-do app works. I could not explain the script out loud, which is the whole problem with vibe coding this part.

## Something new I picked up

A `<label>` makes the words next to a field clickable. `type="email"` and `required` check the value before it sends, and on a phone they pull up the right keyboard. Pressing Enter in a field submits the form. None of that needs JavaScript.

Also: press `.` on any public GitHub repo and it opens in the browser editor. And setting a photo's `width` in CSS does not make the download smaller. The visitor still gets the whole file.

## JS I Don't Understand (from the To-Do App)

- `document.querySelector("#todo-form")`. I get that it grabs the form. I don't get why a typo in that string kills the whole script with no obvious error on the page.
- `form.addEventListener("submit", (event) => { ... })`. The arrow function and `event` showed up together. I don't know what is being passed in, or who calls this function.
- `event.preventDefault()`. If I take it out, the page reloads and the new task is gone. I can see that. I don't know what the "default" is.
- `list.innerHTML = ""` and then `todos.forEach(...)` with `document.createElement("li")`. It deletes the whole list and rebuilds it for one new task. I don't get why it doesn't just add one line of HTML.
- `todos = todos.filter((item) => item.id !== todo.id)`. Delete makes a new array instead of removing one item. I don't get `!==`, or why `todos` has to be `let` for this and not `const`.
- `JSON.parse(localStorage.getItem("todos")) || []` and `JSON.stringify(todos)`. Refresh keeps the tasks, which is cool, but I don't get why the list has to become a string first, or what `|| []` is doing the first time the page loads.
